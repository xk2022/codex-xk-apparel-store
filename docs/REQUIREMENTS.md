# 服飾商城原型需求

版本：原型 v0.1 草案｜日期：2026-11-13  
本版本提供可點擊畫面試作。品牌暫名為「衣序 SELECT」，不是已定案的商標或店名。

## 1. 已確認的營運需求

| 項目 | 已確認內容 |
| --- | --- |
| 建置方式 | XK System 自建網站，不採 SaaS 開店平台 |
| 銷售市場 | 台灣為主，需要超商取貨／付款 |
| 商品 | 款式不定期新增，不設平台商品數量配額；仍按 SKU、圖片容量與流量規劃資源 |
| SKU | 同一款式的顏色與尺寸組合，分別管理供貨狀態及可購數量 |
| 混單 | 現貨與預購可放在同一訂單 |
| 出貨 | 等預購到齊後整單寄出，採一次運費 |
| 顧客 | 允許訪客購買，同時保留會員功能 |
| 營運責任 | 商家負責賣方、收款、出貨與開票；XK System 負責技術方案 |
| 正式串接 | 正式啟用前需確認商家申請資格、服務帳戶與金流／物流／電子發票介接需求 |

## 2. 本輪原型邊界

本輪提供瀏覽器內可操作的畫面、假商品與本機資料狀態，驗證視覺、選購流程及混單資訊。資料使用 localStorage 或執行中記憶體，沒有正式資料庫、多人即時同步或交易保證。

| 包含 | 原型完成條件 |
| --- | --- |
| 首頁與商品列表 | 品牌／穿搭主視覺、商品網格與基本分類／搜尋入口；可進入商品詳情 |
| 商品詳情 | 多圖、商品描述、材質／尺寸示意、顏色與尺寸選擇、數量及現貨／預購標示 |
| 購物車 | 增減／移除品項、合併重複 SKU、計算金額與一次運費、揭露混單出貨規則 |
| 訪客結帳 | 示意聯絡／配送資料、超商取貨與付款方式、模擬付款或下單結果 |
| 會員入口 | 展示會員／查單的預期入口；如有登入畫面，必須清楚標示為模擬，不代表真實認證 |
| 店主後台 | 示意商品／庫存與訂單管理；操作只作用於本機假資料，不能當成正式後台權限保護 |
| 示意訂單 | 顯示訂單明細、供貨／付款／出貨狀態；取消／回補示範需防止本機重複操作 |

正式身分驗證、跨使用者庫存併發、金流、超商物流、電子發票、付款對帳、真實通知與正式環境建置不在本輪實作完成範圍。頁面應提醒使用者勿輸入真實個資、卡號或商家憑證。

## 3. 設計參考

- [Dora Select Shop](https://www.doraselectshop.com.tw/)：主要參考選品氛圍、穿搭與材質細節、商品分類。
- [MOYA](https://www.moya2016.com/)：第二個較簡約的參考，借鑑白底留白、較短導覽與商品優先。
- 第一版採暖白／米色／深灰、少量襯線品牌字、清楚中文資訊、統一商品圖片比例；手機以兩欄、桌機以四欄為設計起點。
- 版面、元件與文案自行製作，不搬用兩個參考站的 Logo、商品照片或文案。示意素材來源與使用條件另見 [ASSET_SOURCES.md](ASSET_SOURCES.md)。
- 錢包、點數、優惠券、收藏、POS 與多倉不是因參考站具有就自動納入的第一版需求。

## 4. 原型示意規則

以下為測試流程用的假設，不是店家正式售價、運費或交期承諾。實作若調整預設，程式、畫面與本文件應一起更新。

| 項目 | 示意值與行為 |
| --- | --- |
| 幣別 | 新台幣，原型價格使用整數元 |
| 超商運費 | 每張訂單一次 NT$65；商品小計滿 NT$2,000 免運 |
| 商品與尺寸 | 商品名稱、價格、材質、尺寸與模特說明均為示意，不能當成真實商品保證 |
| 現貨 | 以本機假資料的 stock 顯示可購數量 |
| 預購 | 有獨立示意備貨天數與可購數量上限，不因款式無配額就允許無限下單 |
| 混單交期 | 以訂單中最長的示意備貨時間呈現整單等待資訊；不推定供應商已承諾到貨日 |
| 付款 | 信用卡與取貨付款僅為流程示意；不收卡號、不建立真實扣款 |
| 持久化 | 本機瀏覽器資料；換裝置、清除資料或重設示範後不保證保留 |

## 5. 購物流程與必要訊息

1. 顧客瀏覽商品，選擇具體顏色／尺寸 SKU 後加入購物車。
2. 商品購買區清楚顯示現貨或預購，以及示意備貨資訊；不可只在長篇商品描述中揭露。
3. 購物車與結帳再次顯示「含預購商品，待預購到齊後整單寄出；採一次運費」。
4. 允許訪客繼續結帳，會員入口不阻擋訪客路徑。
5. 模擬下單前重新檢查本機假資料可購數量與金額，下單後提供可辨識的示意訂單。
6. 取消／庫存回補只能對同一模擬訂單生效一次；取貨付款尚未收款不等於訂單應被自動取消。

## 6. 正式版仍需定案

- 預購交期、延遲通知、供應商限量、取消／退貨／退款及運費政策。
- 線上付款庫存預留期限、貨到付款審核／取消／未取退回規則。
- 品牌正式名稱、Logo、自有照片、首批 SKU 與流量估算。
- 是否串實體店庫存、營運人員與權限、資料保存期限及客服責任。
- 正式技術選型、金物流／發票供應商、商家審核與建置／維護預算。

正式資料模型是 [DATA_MODEL.md](DATA_MODEL.md) 的待審查草案；本輪驗收與證據記錄見 [ACCEPTANCE.md](ACCEPTANCE.md)。
